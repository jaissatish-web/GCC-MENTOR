# Implemented functionality

Production Baseline V1.0 · source `ed06ab8c6c73b63f7be2376e4a90b1e7ab3da342`. This is a source inventory. Hosted signed-in journeys and paid AI outputs require separate runtime evidence.

| Service and entry point | Inputs, processing, persistence and limits |
| --- | --- |
| Landing and legal pages | `app/page.tsx`, `components/landing-v3/` and `app/[legalSlug]/` present the product and publish legal content backed by site content. Employer logos are contextual references. |
| Signup, login, recovery | `/signup`, `/login`, `/forgot-password`, `/auth/update-password` use Supabase Auth through server actions and `/auth/callback` or `/auth/confirm`. Real delivery depends on project callback and sender configuration. |
| Gulf Readiness | `/gulf-readiness` and related routes use country and profile answers. `/api/gulf-readiness` and `lib/gulfReadiness/` score applicable preparedness and return gaps. Missing inputs can leave parts pending. |
| ATS Scan | `/ats-scan`, `/api/ats-scan` and its session endpoint compare resume and target context. Guest rate limits and partial results precede signup/claim via `/api/anonymous-session/claim`. This is an application estimate with no ATS vendor guarantee. |
| Free Tools | `/tools` and `/tools/[slug]` use the registry and calculators in `lib/free-tools/`. The registry contains 50 entries and enables 20 resume and general utilities. Other pages show availability information. Active calculations run in the browser, with local persistence for the application tracker. Use jurisdiction, worker category, effective date and official-source evidence before publishing any country rule. Preserve calculator availability gates and distinguish estimates from eligibility decisions. |
| Career intake and profile | `/onboarding`, `/profile/import`, `/profile/review`, `/profile` take uploaded PDF or DOCX, pasted text or manual details. `/api/parse/`, `/api/career-intake/` and `/api/profile/` extract, stage and save reviewed fields. Photo, skills, certifications, typical duties and visibility have their own handlers. Optional gaps can be deferred; confirmed profile data and unresolved date precision are preserved. |
| Dashboard and readiness indicators | `/dashboard` and `/api/dashboard/overview` surface profile completion, work in progress, packages and next actions. `lib/readiness.ts` measures profile completeness separately from Gulf Readiness and job fit. |
| Career Profile Resume | `/create-resume`, `/templates` and `/api/packages/career-profile` generate a base resume from the saved profile. Profile facts are edited in Career Profile. Presentation is configured through the template and style controls. |
| Job match and optimize | `/optimize/target`, `/optimize/setup`, and `/optimize/generate/[packageId]` collect role, job description and preferences. `/api/optimize/analyze`, `check`, `confirm-skills` and generation apply fit and AI workflow rules. The result is a per-target package with preview, saves, template settings, and guarded generation. Pending precision can prevent an experience assessment. Returning to the target step restores the tab's title, industry and advert if Career Profile defaults fail to load, except when the profile request denies access. The advert input exposes its matching guidance to assistive technology. |
| Resume Library and package editing | `/dashboard/library`, `/package/[id]`, its edit page and `/api/packages/` manage owner-scoped packages, snapshots, reusable drafts, application stages and document edits. Related artifacts persist under the target package. Cover Letter, Interview Q&A and Mock Interview reopen the selected job when the browser navigates to a different saved package on the same service page. A change in the resume picker updates that page’s package URL so refresh preserves the selection. |
| Exports and file check | `/api/resume/pdf` and package `pdf`, `docx`, `file-check` and `ats-score` handlers assemble owner-authorized exports and diagnostics. The PDF browser and DOCX engine render independently. A render failure can prevent download without removing the package. |
| Cover Letter | `/cover-letter` and package `cover-letter` handlers use profile evidence and target context, check authorization, save drafts and allow editing through the letter ID subroute. |
| Interview Q&A | `/interview-qa` and package `interview-qa` use target and confirmed evidence, validate model output and save question and answer sets for review. |
| Mock Interview | `/mock-interview`, package `mock-interview/start` and run `answer`, `voice`, `finish` handle question practice, submitted answers, transcription when enabled, and final feedback. `/api/mock-interview/progress` exposes owned history and progress; voice capabilities determine recording availability. |
| Preparation Pack | `/preparation-pack` leads into grouped preparation services using existing packages. Each service applies its own availability and credit rules. |
| LinkedIn and NaukriGulf | `/linkedin-optimization` and `/naukrigulf-optimization` link to workspaces. Their API directories handle import, guarded generation and users' saved drafts. Users can review and copy drafts for use on the external platforms. |
| Account, settings and referral wallet | `/settings`, `/settings/referrals`, `/professional-profile`, referral endpoints and settings actions cover account and profile navigation, referral links, share, qualification status, wallet history and account controls. See [Business](BUSINESS.md). |
| Admin | `/admin` and its access-log, users, AI-provider, prompts, packages, plan, promo-codes, referrals, content and services sections expose authorized configuration and monitoring. Server actions recheck access. |
| Internal workers and helpers | Retention and voice-review route handlers use `CRON_SECRET`. Pending-draft, recreation status, referral visit and service usage/credit endpoints support the user journeys above. `/resume-design-lab` is a separate gated source route. |

API handlers validate input and ownership in context. Typical outcomes include sign-in or access errors, validation feedback, allowance/credit denial, and retryable service failures. For specific response contracts inspect the handler and associated tests. For AI and billing limits see [AI](AI.md) and [Business](BUSINESS.md).
