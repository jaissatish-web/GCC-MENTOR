# Universal Career Profile Builder 2.0

Approved by Satish, 1 November 2026. Status: audit and implementation in progress; not released.

## Authorized outcome and protected scope
Extend the existing resume intake, authenticated review and canonical editor with evidence-based diagnostics, profession-aware questions, one-at-a-time correction, actual field coverage, explicit verification and an honest improvement summary. Reuse the existing parser/provider/import review, pending draft, recovery, validation and atomic save. No schema migration, paid service, scoring formula, authentication, subscription, downstream-service or unrelated design changes. Preserve source evidence and never silently accept factual suggestions. Merge via PR only after required CI passes; monitor automatic production deployment without manual redeployment or secret changes.

Optional sections and writing suggestions remain optional. Detect date uncertainty/overlaps without declaring employment false. Corrections route to existing typed controls; facts and changed values invalidate prior confirmation. Preserve per-import tab recovery. Before/after counts must derive from actual current and baseline conditions; original uploaded file is never represented as repaired. Test profession/career/country diversity with synthetic fixtures; run typecheck, lint, full suite and production build, plus responsive browser checks at 320/375/390/430px. ## Implemented architecture and compatibility
- Inputs remain existing ResumeImport, public intake, onboarding upload/paste and canonical manual editor. PDF/DOCX layout extraction, schema normalization, first-reading repair, conservative wording gate, AI provider/model configuration, limits and reservation behavior are reused.
- New careerDiagnostic is a deterministic read-only projection; no new model request, score, dependency, schema or public report route. Recorded-field bars disclose numerators, denominators and applicability. Optional education/certification/project bars appear only for recorded entries. Unknown dates never produce invented duration; concurrent roles are review advisories. Gap advisories require a complete known timeline, union overlaps and treat breaks as valid.
- CareerDiagnostic shows original extraction counts, source-reader text, field comparisons, optional profession/work-context questions and skills display groups. Controls tailor this review only; career facts still use the canonical editor. Profession detection is an editable keyword heuristic, not verified occupational classification. Country context stays neutral; no new legal/licensing eligibility claims.
- ResumeAcceptanceReview presents diagnostics before one-field factual corrections and one-section wording review. Missing facts use existing typed controls; accepting a suggestion never confirms unrelated facts. Actual source-warning verification is bound to import/version/value/reason using existing SHA-256 helper. Changed values invalidate confirmations. Marker recovery retains active steps and value-bound deferrals in the same private tab; final save always needs a fresh explicit acknowledgement after reload.
- Before/after reports count actual validation conditions, supplied fields, explicit source-value confirmations, section edits, accepted/kept/unselected suggestions. This does not claim to repair an original PDF/DOCX. Final preview includes current-versus-unconfirmed employment state and every applicable editable section.
- Manual first-profile entry also enters final review before its first PUT. Older/manual reviews without an authoritative server import identity disclose that edited selections cannot recover after refresh; keep the tab open until saving. File selections cannot survive a reload. Authenticated imports reuse existing private pending-draft and stale-version controls.
- Profile PUT, profile children/category data contracts, owner isolation, atomic persistence, existing validation and all downstream services are preserved. Successful review save redirects to existing /dashboard. No production database/configuration changes.
- Processing UI now marks only actual input selection complete and keeps combined extraction/checking active until the non-streaming response. No fabricated intermediate completion or percentages. Selected upload files remain retryable in memory where safe.
- Extraction prompt retains output schema and fact-only rules, extends universal wording and explicitly treats resume instructions as untrusted source data. Parse failure logs keep codes and omit provider exception detail that could contain source content. This reduces disclosure risk; a prompt instruction is not a guarantee against arbitrary model errors.
- Builder-local light tokens reuse shared semantic styles and typography. Existing application shell/navigation and unrelated pages keep their theme. Reduced motion and existing touch targets remain.

## Limits and production verification
No OCR or original binary retention was introduced. Comparison uses reader text and structured fields, not invented PDF coordinates or a reproduction of source layout. Unreadable/image-only files retain existing retry/paste errors. No claim that every ATS parser behaves alike or that any employer rejected a document. Optional display skill groups are user-classified, not AI proficiency. Live provider fidelity, actual signed-in production upload/creation and cross-device synchronization are not certified by local fixtures; founder participation may be needed for the real account journey. Existing downstream automated contracts/regressions are exercised, not real payments or paid service calls.
