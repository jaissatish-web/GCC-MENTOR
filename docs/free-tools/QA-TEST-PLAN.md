# QA test plan

Per tool before next implementation: normal/zero/negative/missing/NaN/huge/decimal inputs; invalid/leap/reversed dates and boundaries; expected independent fixture outputs. Pure-function tests use existing Node/TypeScript tooling and fail on incorrect results. Legal fixtures include official reference examples, regimes, exclusions and transition boundaries. Do not certify formulas from self-generated expected values.

Browser: guest and simulated member CTA states; real authenticated production checks separately marked unavailable without configured session.360,390,768,1440px and200% zoom, overflow, labels, keyboard/focus/live announcements, copy rejection/fallback, reset, print, storage unavailable/corrupt/import/export. Inspect network: no AI/profile API or raw-input analytics. Check browser console/hydration. Test every published route's canonical, unique title/description, SSR useful content/schema, sitemap, related link destinations and robots. Test unknown slug404. Required existing typecheck/lint/test/build and GitHub checks must pass. Run Lighthouse on representative catalog/calculator/text/utility pages with documented mobile conditions. Record actual coverage and missing evidence; source inspection is not live certification.
