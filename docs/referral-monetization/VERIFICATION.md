# Preproduction verification

## Final review on 26 November

**Production decision** — Hold for founder approval and the open hosted release checks. Production baseline was `b512824`. The [protected Ready Preview](https://gcc-mentor-c02macw8w-satishs-projects-c02c354b.vercel.app) at `a2c35a9` shared application code with the previously verified head `477eb3b`, which passed [CI #1107](https://github.com/jaissatish-web/GCC-MENTOR/actions/runs/45764028706). Hosted results below apply to that application revision.

- **Wallet retry defect.** A local reproduction of a lost success response followed by a temporary error reading the saved artifact caused a new operation ID on the third request. With available credits the wallet could treat it as a second paid generation. The patch keeps the original operation ID across this specific error and restores a new ID after a successful replay. The regression check simulates one settlement, a temporary replay error and recovery of the same saved artifact.
- **Rollout and isolation.** The hosted GCC-MENTOR-TEST catalog audit found RLS enabled on all 13 new tables, zero anonymous or authenticated table privileges and zero anonymous or authenticated execute grants across the 23 new functions. Referral and wallet enforcement default to off. The disposable wallet check confirms new requests bypass wallet enforcement with the flag off while an existing reservation still settles and replays its result. Apply and verify migrations before serving the new app because the app checks wallet availability even while enforcement is off.
- **Service comparison.** The new premium entry points add wallet reservations and atomic settlement. The existing AI guards, provider selection and service writers remain in use. The recorded interview uses the existing voice session creation with wallet settlement, then the unchanged upload, transcription, feedback and report pipeline. Career Profile continues to use its existing writer with a referral qualification step after save. Readiness, ATS scoring and export implementations were unchanged in the baseline comparison.
- **Recovery follow-up.** The forgot-password handler and Auth callback are unchanged from production. The branch adds an isolated Preview default for site origin. The prior hosted signup confirmed its identity but landed on the correct Preview hostname at `/` instead of `/auth/callback`. Recovery later returned 429. For the final retry, the test inbox had no existing Test account. A confirmed disposable account was provisioned without signup mail and removed when approval review denied access methods that would mint or reuse a protected Preview share link. No new email was sent. The current rate-limit status, exact redirect cause and end-to-end recovery are unverified.
- **Complimentary generation.** Live Preview Cover Letter generation with an approved temporary provider configuration saved one letter and used exactly one complimentary allowance on a zero-credit account. Replay returned the same letter, a fresh request was rejected, and there were no wallet charges or remaining holds. Temporary QA configuration and fixtures were removed.
- **Recovery plan.** The founder approved the rehearsed migration rollback and synthetic restore as the release alternative. An actual production data restore cannot be verified from the synthetic rehearsal.
